# Xバズ自動化プロジェクト 要件定義書

## 1. 目的・背景

- 起業系・X攻略・SNS系として運用しているXアカウントを、Claude Codeで段階的に自動化する。
- バズっている投稿にコメント・引用リツイートで反応し、いいね・RT・フォロワーを獲得しながら、将来的にアカウントを収益化(マネタイズ)する。
- 対象ポストや反応の判断・生成はAI(Claude)が担い、人間は選択・確認の負担を最小限にする。
- 最終的には完全自動化を視野に入れつつ、初期は半自動運用(AIが生成→人間が最終確認して投稿)から開始する。

## 2. 全体ワークフロー

```
① バズポスト自動取得(config.yamlの閾値・ジャンルでフィルタ、3〜30件ランダム)
        ↓
② 投稿の分類(通常/シリアス系/経験談内省系/ネタ・ミーム系/広告 のいずれか)
        ↓
③ 投稿者の著名人判定・影響力ランク判定(S/A/B/C)
        ↓
④ 該当すればリサーチ(著名人本人の公的な実績・発言のみ。私人のプライバシーは対象外)
        ↓
⑤ 返信欄の分析(いいねが多い返信の"型"を抽出し、それを超える視点で生成)
        ↓
⑥ 分類結果に応じて使用可能パターンを絞り込み(pattern_eligibility参照)
        ↓
⑦ 生成(共通ルール+パターン別指示+著名人addon+セルフチェックループ)
        ↓
⑧ アプリ画面に候補を表示(投稿主とセットで一覧表示)
        ↓
⑨ 人間がクリックで選択・投稿、またはスキップ
        ↓
⑩ ログ記録・後の分析に利用
```

## 3. 運用ルール(config.yamlに集約)

- 巡回・投稿間隔、稼働時間帯(非稼働:深夜1時〜朝6時)、1日の合計アクション数(10〜20件、目安15件)、内訳比率(自分発信2:コメント6:引用RT2)は全てプルダウンで変更可能。
- バズ判定はいいね数・RT数・経過時間の閾値+伸び率スコアリング(いいね数÷経過時間)。
- 動作モードは「手動/半自動(要確認)/完全自動」から選択。
- 詳細は添付の `config.yaml` を参照。

## 4. 除外・見送りルール

- 広告(スポンサード)ラベル付き投稿は自動スキップ。
- 断定的な副業・稼げる系セールスコピーには肯定的に便乗しない。
- 政治(党派・政策論争)、宗教、アダルト、差別・ジェンダー論争、医療の断定的アドバイス、投資の断定的助言、他人の炎上への便乗、著作権グレーな話題は除外。
  - ただし業界の規制・構造批判(タクシー業界の規制緩和など)は経済ジャンルとして生成可。
- 事件事故・訃報・災害・スポーツは「要注意」扱いで、慎重モード(serious_mode)を適用しつつ生成可。
- 投稿に映り込む私人(著名人の家族・交際相手など)のプライバシーには一切触れない。未成年の子どもへの言及は絶対禁止。
- 刑事有罪判決・重大な炎上歴がある人物の投稿は、都度判断の上、原則見送りを推奨。

## 5. 生成の中核原則

**最上位原則:** 元投稿をそのまま/言い換えて繰り返さない。必ず「自分の中で一度別の形に変換してから返す」。

### 生成ループ(全パターン共通)
①ドラフト作成 → ②自己チェック(元投稿固有の要素を含むか/汎用テンプレートになっていないか) → ③NGなら書き直し(最大3回) → ④OKなもののみ出力。

### 型(着地パターン)
- **型A(再解釈型)**:主張→具体的数字・事実→見立てで締める
- **型B(自問自答→問いかけ型)**:考えの過程を見せ、「〜なんでしょうか・・」で締める
- **型C(再定義+比喩転用型・最優先)**:元投稿の語彙・比喩ドメインを借りて別概念に転用
- **型D(実例展開型・引用RT/自分発信用)**:現象→理由→実例→実例の延長で深掘り→オチ、の5段階。オチに早く飛びつかない。珍しい実例の後は身近な日常例で一般化する。

## 6. コメントパターン(10種+拡張2種)

1. 共感・肯定型
2. 分析・解説型
3. データ・事実補強型
4. 具体ノウハウ追加型
5. 逆張り・問題提起型
6. 経験談リンク型
7. 質問返し型
8. 短文インパクト型
9. ユーモア・軽口型
10. 著名人リスペクト型
11. 著名人いじり・ツッコミ型(適用条件:本人が自虐ネタとして公にしている場合のみ)
12. ミーム・ノリ便乗型

## 7. 引用リツイートパターン(4種)

1. 意見主役型
2. 要約・翻訳型
3. 実例接続型
4. インプレッション狙い(フック)型

オープナー(「これはまさにそう」「10年前とは違いますね」等)は固定貼り付けではなく、トーンの参考として生成方針に組み込み、毎回生成する(`quote_opener_policy`参照)。

## 8. パターン適用ルール(投稿分類ごと)

詳細は `config.yaml` の `pattern_eligibility` を参照。概要:

| 分類 | 使用可能パターン | 備考 |
|---|---|---|
| 通常投稿 | 全パターン使用可 | - |
| シリアス系(事件・災害等) | コメント[1,2,3,7,15,16,19] / 引用RT[2] | serious_mode適用、見送り可 |
| 経験談・内省系 | コメント[1,2,4,6,7] | ユーモア・軽口・ミーム型は除外 |
| ネタ・ミーム系 | コメント[8,9,12] / 引用RT[3] | - |
| 広告投稿 | 生成せず自動スキップ | - |

## 9. アカウントキャラクター設定

- 一人称:私
- 口調:コメント(リプライ)は話しかける口調(「〜ですよね」)、引用RT・自分発信はタメ口寄り
- 絵文字:たまにはOK(感情が強く動いた時のみ、連続使用しない)
- 「ｗ」:温度が軽い投稿では積極使用、シリアス系・経験談内省系では不使用
- コメント文字数目安:1〜3文

### 人格の"揺らぎ"設計(重要)
返信履歴全体で「隙のない優等生」に見えないよう、深掘り型(型A〜D)と、力の抜けた軽いノリ・素朴な質問・ツッコミを、投稿の温度感に応じた自然な比率(目安3割程度)で意図的に混ぜる。シリアス系・経験談内省系では軽いノリを使わない。

## 10. 著名人・インフルエンサー対応

詳細は `influencer_addon.txt` を参照。要点:

- 著名人本人の公的な実績・発言はリサーチ対象。交際相手・家族等の私人のプライバシーは対象外(未成年の子どもへの言及は絶対禁止)。
- 影響力ランク(S/A/B/C)に応じてリサーチの深さを変える。全件フルリサーチはコスト面で非現実的なため、候補上位のみ徹底リサーチする2段階方式。一度調べた人物情報はキャッシュして使い回す。
- 投稿を表層的に受け取ってよいか、過去の文脈を踏まえるべきかを生成前に判定する。
- リスクフラグ該当者(有罪判決等)は都度判断、原則見送りを推奨。

## 11. ファイル構成

```
📁 x-buzz-project
 ├─ common_rules.txt        # 全パターン共通の絶対ルール・トーン・型・生成ループ
 ├─ influencer_addon.txt    # 著名人/インフルエンサー対応の追加指示
 ├─ config.yaml             # 数値・閾値・ジャンル・パターン適用ルールなど可変設定
 └─ 要件定義書.md            # 本ファイル
```

今後、コメント・引用RTの各パターンの実際のプロンプト文面を `prompts/comments/comment_01.txt` 〜 `10.txt`、`prompts/quotes/quote_01.txt` 〜 `04.txt` として個別ファイル化することを推奨(現時点ではcommon_rules.txt内に型として集約されている)。

## 12. アプリ画面要件

### 画面構成
- **ホーム(今日の候補)**:稼働ステータス、本日の実績サマリー、アクション内訳、取得・ポスト作成ボタン、候補一覧(左=投稿主、右=生成候補の左右分割形式)
- **ログ・分析**:昨日のインプレッション・前日比、週間フォロワー推移、いいね/RT数の推移、投稿種別ごと・パターンごとの成果比較(未実装、今後設計)
- **設定**:運用スケジュール、アクション内訳・モード、ジャンル・バズ閾値、除外ルール、著名人・インフルエンサー対応、キャラクター設定をカテゴリカードで表示し、プルダウン・トグルで変更可能

### 候補一覧の操作
- 「取得」ボタン:ランダムに3〜30件のポストを一括取得(ジャンル別に自動分類)
- 「ポスト作成」ボタン:取得した投稿に対して、内訳比率に沿って自動でコメント/引用RT/自分発信を振り分けて一括生成
- 各候補行:種別(コメント/引用RT)・使用パターンをプルダウンで変更可能、候補違いをプルダウンで切り替え、再生成ボタンあり
- 「この案でGO」ワンクリックで投稿、スキップも可能
- 広告等の除外投稿はグレーアウト+除外理由を表示

### モード
- 手動:AIが候補生成→人間が選択→人間が投稿
- 半自動(初期運用の推奨モード):AIが生成→人間が最終確認→投稿
- 完全自動:AIが生成→自動選択→自動投稿(将来的な移行先)

## 13. 未確定・今後の検討事項

- **自分発信投稿(オリジナルポスト)専用のパターン一覧**が未確定。型Dは引用RT/自分発信共通の型として使えるが、自分発信専用のパターン分類(ノウハウ発信型、問題提起型など)はまだ整理されていない。
- **反応後のフォロワー化・収益化の導線**が未設計(良いコメントをした後、フォロワー化にどうつなげるか、収益化の具体策)。
- **自分のコメントへの返信が来た場合の対応方針**(会話を続けるか、放置するか)が未定義。
- **マルチアカウント対応**は現時点で見送り、単一アカウントで運用開始する。
- **risk_flagged_accountsの判断基準**が「都度判断」のままで、判定基準の一貫性を保つ仕組みは未整備。
- 実装時のAPI利用コスト・処理速度は、実際にClaude Codeで実装した上で検証が必要。

## 14. 技術面の注意点(Claude Codeへの申し送り)

- X APIの投稿取得・投稿にはレート制限があるため、1回の巡回での取得件数・API呼び出し回数を制御すること。
- 著名人の徹底リサーチは全件に行わず、候補上位のみに絞る2段階方式とすること。一度調べた人物情報はキャッシュすること。
- 広告ラベルの検出は通常のバズ閾値ロジックでは拾えないため、取得ステップに専用の判定を追加すること。
- 生成ループ(セルフチェック&書き直し、最大3回)をプログラム側で強制的に実行させる設計にすること(プロンプトに書くだけでは徹底されないことが判明したため)。
- 設定画面の変更は、config.yaml(またはDB)に即時反映される構造にすること。
