# x-ai-editor

X(旧Twitter)投稿のネタ作りを半自動化するためのプロジェクトです。
初心者の方でも迷わないように、フォルダの役割と使い方をここにまとめます。

## 全体の流れ(将来像)

1. `input/input.txt` にニュースやX投稿を貼る
2. 「振り分けGPT」が内容を読み、使う専門GPTを選ぶ
3. 選ばれた専門GPTへ素材と指示を送る
4. 各専門GPTの回答を集める
5. 「編集長GPT」がまとめて最終候補を1〜3案に絞る
6. 結果をPC上のファイルに保存する

## 大事な設計方針(途中で変更しました)

当初はChatGPTのブラウザ画面を自動操作する方式を検討していましたが、
以下の理由から**Claude API を直接呼び出す方式**に変更しました。

- ChatGPTの画面を自動操作するには「人がブラウザを見ながら手動ログインする」
  作業が必須ですが、この作業環境(クラウド上)には画面がなく実現できません。
- 複数の「カスタムGPT」の画面を自動操作してやり取りする方式は、
  OpenAIの利用規約に触れる可能性があります。
- APIを直接呼び出す方式なら、ブラウザ操作やログインが一切不要で、
  画面のデザイン変更で壊れる心配もありません。

「振り分けGPT」「コメントGPT」などの役割は、ChatGPTのカスタムGPTではなく、
`prompts/` フォルダに保存したプロンプト(指示文)を使って、Claude APIを
直接呼び出す形で実現しています。役割ごとの人格・ルールはこれまで通り
自由に書き換えられます。

## フォルダの役割

| フォルダ / ファイル | 役割 |
| --- | --- |
| `input/input.txt` | 自分でニュースやX投稿を貼る場所 |
| `prompts/` | 各GPT役割のプロンプト(指示文)を保存する場所 |
| `config/gpts.json` | 各GPT役割の名前・有効/無効などの設定 |
| `outputs/` | 各専門GPTの回答を保存する場所(run_idごとにフォルダ分け) |
| `final/` | 編集長GPTの最終回答を保存する場所 |
| `automation/` | 自動化プログラム(スクリプト)を置く場所 |
| `logs/` | 実行結果やエラーの記録を残す場所 |

## 現在使えるコマンド

`x-ai-editor` フォルダの中で実行してください。

初回だけ、必要な部品をインストールします。

```bash
npm install
```

### input.txt を読み取る

```bash
npm run read-input
```

`input/input.txt` に貼った内容を読み取り、「読み込み成功」「文字数」「プレビュー」を
表示します。空の場合は「input.txt に素材がありません」と表示されるだけで、
エラーにはなりません。

### ブラウザが正しく動くか確認する(参考機能)

```bash
npm run test-browser
```

自動化用のブラウザ(Chromium)が正しく起動できるかを確認する動作テストです。
現在の設計ではGPTとのやり取りにブラウザは使いませんが、動作確認用に残しています。

### 振り分けGPTを実行する

```bash
npm run router
```

`input/input.txt` の内容を「振り分けGPT」へ渡し、どの専門GPTを使うべきかの
判断結果を `outputs/<日時>/router.txt` へ保存します。

### 振り分け→専門GPTまで一括実行する

```bash
npm run generate
```

素材を振り分けGPTへ渡し、その判断結果を読み取って、必要な専門GPT(最大5体)
だけを自動で実行します。結果はすべて `outputs/<日時>/` フォルダの中に、
`router.txt` `meme.txt` のようにGPTごとのファイルで保存されます。
振り分け結果がうまく読み取れなかった場合は、安全のため専門GPTへは送らず停止します。

**Claude APIキーを設定していない場合は、ダミー(モック)応答で動作確認だけできます。**
実際にAIの回答を得たい場合は、`x-ai-editor` フォルダ内に `.env` ファイルを作り、
以下のように書いてください(`.env` はGit管理対象外です)。

```
ANTHROPIC_API_KEY=ここに自分のAPIキー
```

## プロンプト(GPTの指示文)を直すには

`prompts/` フォルダの中の、直したい役割のファイル(例: `meme.txt`)を
そのままテキストとして編集して保存するだけです。次回の実行から反映されます。

## ログについて

`logs/history.log` に、実行日時・処理名・成功や失敗などの結果が
1行ずつ追記されます。パスワードやAPIキーなどの秘密情報は記録しません。
